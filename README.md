# skill-pack

Behavioral skills for AI coding tools. Drop them into Claude Code, Gemini CLI, Cursor, Windsurf, GitHub Copilot, Cline, Amp, Kiro, and Roo Code — they inject instructions directly into the LLM's context.

No code runs. No server. No dependencies. Just markdown files with instructions.

---

## Install

```bash
git clone https://github.com/XavierLasierra/skill-pack
cd skill-pack
bash install.sh
```

The installer detects which tools you have and copies skills into the right config files. Re-running **syncs**: updates changed skills, removes skills deleted from the repo, and adds new ones.

```bash
bash uninstall.sh   # removes everything it added
```

> **Single source of truth:** `skills/` is the only thing committed. All template files (`.clinerules`, `.github/copilot-instructions.md`, `AGENTS.md`, `.roorules`, `.kiro/`) are generated by `install.sh` and gitignored — they can never drift out of sync.

### Options

```bash
# Install only to specific tools (bypasses auto-detection)
bash install.sh --tools claude,cursor

# Install only specific skills
bash install.sh --skills concise,conventional-commits

# Combine both
bash install.sh --tools claude --skills clean-code,concise
```

## Hook system (Claude Code)

Skills injected once into `CLAUDE.md` work but drift — the LLM gets verbose over long sessions. Hooks fix that.

`install.sh` automatically registers two hooks and a status line in `~/.claude/settings.json`:

| Setting | What it does |
|---|---|
| `hooks.SessionStart` | Injects active concise level rules on startup |
| `hooks.UserPromptSubmit` | Reinjects rules every turn — prevents drift |
| `statusLine` | Shows active level in the status bar (`concise:full`) |

Hook scripts are installed to `~/.skill-pack/hooks/`. Active level persists in `~/.skill-pack/concise-level`.

### Switching levels

```
/concise lite    # drop filler only, keep sentence structure
/concise full    # drop articles, filler, pleasantries, hedging (default)
/concise ultra   # maximum compression, noun phrases and imperatives only
/concise off     # disable concise mode
/concise         # show current level
```

Hooks are Claude Code only. Other tools (Cursor, Windsurf, Gemini) use the static skill file — same direction, less enforcement.

## Add your own skill

Create a skill in the appropriate group directory, e.g. `skills/code-quality/my-skill.md`:

```markdown
---
applies_to: all
---
## My Skill — Active

### Do
- Specific rule the LLM must follow

### Don't
- Specific thing to avoid

Be specific — vague instructions get ignored.
```

Run `bash install.sh` again — it picks up new skills automatically.

### `applies_to` field

Controls which tools receive the skill. Values: `all`, or a list of tool names.

```yaml
---
applies_to: [claude, gemini, cursor, windsurf]
---
```

Valid tool names: `claude`, `gemini`, `cursor`, `windsurf`, `copilot`, `cline`, `amp`, `kiro`, `roo`.

Omit the field (or use `all`) to install everywhere.

## How it works

Each skill is a plain markdown file. The installer appends them to the config file each tool reads on startup, wrapped in markers:

```
# >>> skill-pack:communication/concise
[skill content]
# <<< skill-pack:communication/concise
```

The markers let `install.sh` and `uninstall.sh` operate without touching anything else in your config.

Re-running `install.sh` **syncs** the config against `skills/`:
- **Updated** — skill exists, content changed → block replaced in-place
- **Removed stale** — skill deleted from repo (or `applies_to` no longer includes the tool) → block pruned
- **Installed** — new skill → block appended

Partial installs (`--skills foo,bar`) skip pruning — only the selected skills are touched.
